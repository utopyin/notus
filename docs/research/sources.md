### Devbox implementation validation

The [devbox results](devbox-results.md) record the 2026-09-13 checks. Application code uses a maintained fetch-based Namespace wire client, not the unpublished SDK wrapper. The published SDK `1.0.0` was installed only in temporary inspection tooling for explicit user-login credential issuance. Namespace CLI `0.0.185` built and registered the private images. The live Create API required native `instanceShape`; the newer descriptor's `machineSize` did not suffice.

The image uses Herdr release `v0.9.0`, built from `b99002ac99b09e00b4ca692436cb15a6b0d676f1`, and the Bun `1.4.2` Linux x64 baseline archive. Both download checksums in `apps/devbox/Dockerfile` were verified. Herdr's released protocol schema matches the inspected protocol-22 schema; the application uses a narrow native socket client rather than the incompatible Herdr SDK graph. Ubuntu's AMD64 manifest is pinned in the Dockerfile, but apt repositories are not frozen. Follow-up runtime checks establish initial Namespace Herdr readiness with a named image user and an explicit Create session. They do not establish stop/start readiness, production provisioning or real model execution; detailed evidence and current OCI identities remain in [devbox results](devbox-results.md).

## Updates and distribution

Keep `repos/` read-only during implementation. Use normal dependencies or separately built pinned artifacts, never imports from a subtree. An authorized reference refresh uses the directory, URL, and ref above:

```sh
git subtree pull --prefix=repos/effect \
  https://github.com/Effect-TS/effect.git main --squash
```

Subtree updates create commits. Begin with a clean tree, update this inventory, and recheck affected evidence. Updating sources does not update the root catalog or prove compatibility. Build upstream artifacts in a separate checkout, not `repos/`.

Top-level licenses: Effect and Herdr SDK MIT; Herdr and Alchemy Apache-2.0; Plannotator MIT OR Apache-2.0. Namespace declares Apache-2.0, but the inspected tree and public archive lack the advertised standalone license file. Confirm that before redistribution. These are not transitive license/SBOM audits or hosted-service entitlements. Plannotator's `SECURITY.md` supports only its latest released version for security fixes.
